## 2. 분석 대상

## 3. 워크플로우

### 3.1 초기화 — 팀모드 (최초 1회)

1. tmux 실행 여부 확인 → 미실행 시 솔로모드(3.2로 직행)
2. TeamCreate → 팀 생성
3. 분석팀원1~3 스폰 (업무 미할당, 대기) → monitor 최후 스폰 (active pane 확보)
4. `/usage-monitor start` → 사용량 확인
5. `normal`(<90%) → 최대 3명에게 각 1건씩 할당 / `stop`(≥90%) → 전원 대기, 리셋 후 재확인

**스폰 시 프롬프트 템플릿:**
```
M30 레거시 서비스 분석팀원입니다.
팀리더(team-lead)의 SendMessage 지시를 대기하세요.
지시 없이 스스로 작업을 시작하지 마세요.
```

**업무 할당 SendMessage 템플릿:**
```
/analyze-service {SERVICE_ID} 분석을 수행하세요.
완료 후 SendMessage로 팀리더(team-lead)에게 보고하고, 다음 지시가 올 때까지 대기하세요.
추가 서비스를 스스로 시작하지 마세요.
```

### 3.2 분석 반복

**상태**: ⬜ 미분석(할당 가능) → 🔄 분석 중(중복 할당 금지) → ✅ 완료

**매 iteration:**
1. 체크리스트 읽고 ⬜ 확인. ✅/🔄 건너뜀. 전부 ✅이면 종료(4.4)
2. ⬜ 서비스 **1건** 선택 → 즉시 🔄 마킹
   - **챕터 분산**: 팀원별로 서로 다른 챕터(### 절)를 우선 할당
3. 완료 보고(SendMessage) 수신 → 🔄→✅ 갱신 → 요약 테이블 +1
4. **컨텍스트 초기화** (아래 명령어를 Bash 도구로 **한 글자도 변경 없이** 실행):
   ```bash
   tmux send-keys -t {paneId} '/clear' && sleep 10 && tmux send-keys -t {paneId} Enter && sleep 10 && tmux send-keys -t {paneId} Enter
   ```
   - `/clear`와 `Enter`는 **별도 send-keys로 분리** (합치면 실패)
   - `{paneId}`: 팀원의 tmux pane ID (예: `%14`). 종료 알림의 `paneId` 필드에서 확인
   - SendMessage로 /clear 보내기 금지
5. 초기화 완료 후 **SendMessage로 다음 ⬜ 1건 할당**
6. 실패 시 🔄→⬜ 복원. 컨텍스트 한계까지 **멈추지 않고** 반복

**1건씩 할당 원칙**: 스폰 시에도, 후속 할당 시에도 **항상 1건만**. 복수 할당 시 팀리더 통제 불가.

**품질 요구사항**: SQL(목적·테이블관계·바인드변수·컬럼 상세, 비즈니스 의미 해석) | UI(레이아웃+이벤트핸들러+데이터흐름) | Java 없으면 '없음' 명시 | E2E 데이터흐름 다이어그램 | 특이 로직 별도 강조

## 4. 팀모드 규칙

### 4.1 팀 구성

| 역할 | name | 설명 |
|------|------|------|
| 팀리더 | team-lead | 전체 관리, 업무 분배, 사용량 확인 |
| 분석팀원1~3 | 분석팀원1~3 | 팀리더 지시에 따라 분석·보고 |
| monitor | monitor | 사용량 조회용 pane (최후 스폰) |

**신규 팀원 생성 금지** — 병렬 처리 필요 시 팀원 내부에서 Task 도구(서브에이전트) 사용.

### 4.2 사용량

- `normal`(<90%) → 최대 3명 할당 / `stop`(≥90%) → 신규 할당 중단, 팀원은 대기 유지(소집해제 금지), 리셋 후 재개
- 스킬: `/usage-monitor start`, `/usage-monitor check`

### 4.3 행동 규칙

- 팀리더는 **이벤트 기반** — SendMessage 수신으로 반응. **sleep+capture-pane 폴링 금지**
- capture-pane 허용: 10분 이상 무응답(장애 의심), 프로세스 생존 확인, 디버깅 시만
- 상태 확인: TaskList 조회
- 팀원 소집해제는 **최종 종료 시에만** (사용량 조절 목적 해제 금지)

### 4.4 종료

모든 팀원 shutdown_request → `/usage-monitor stop` → TeamDelete(선택) → 최종 체크리스트 확인
