## 3. 작업 워크플로우

### 3.1 초기화 (최초 1회)

1. tmux 실행 여부 확인 → 실행 중이면 팀모드 활성화 (섹션 4 참조)
2. 솔로모드 시: 초기화 없이 3.2로 진행
3. 팀모드 시 아래 순서를 **반드시** 따른다:

   **① TeamCreate** → 팀 생성

   **② 팀원 전원 스폰** → 분석팀원1~3 스폰 (업무 미할당, 대기), monitor 최후 스폰 (active pane 확보)

   **③ /usage-monitor start** → 초기 사용량 확인

   **④ 업무 분배** → action 결과에 따라 분석팀원에게 서비스 할당
   - `action == normal` (<90%) → 최대 3명에게 각 1건씩 할당
   - `action == stop` (≥90%) → 전원 업무 할당 보류, 리셋 시각까지 대기. 리셋 후 재확인

**⚠️ 주의: 팀원은 초기화 단계에서만 호출한다. 3.2 분석 반복 중에 신규 팀원을 추가 호출하지 않는다.** 병렬 처리가 필요하면 기존 팀원 내부에서 Task 도구(서브에이전트)를 사용한다.

**⚠️ 1건씩 할당 원칙**: 팀원 스폰 시 **서비스 1건만** 할당하고, "완료 보고 후 대기"를 명시한다. 복수 서비스를 한번에 할당하면 팀원이 SendMessage(축소/중단 지시)를 확인하기 전에 다음 서비스를 자동 시작하여 팀리더의 통제가 불가능해진다.

**스폰 시 프롬프트 템플릿 (업무 미할당, 대기):**
```
M30 레거시 서비스 분석팀원입니다.
팀리더(team-lead)의 SendMessage 지시를 대기하세요.
지시 없이 스스로 작업을 시작하지 마세요.
```

**업무 할당 시 SendMessage 템플릿:**
```
/analyze-service {SERVICE_ID} 분석을 수행하세요.
완료 후 SendMessage로 팀리더(team-lead)에게 보고하고, 다음 지시가 올 때까지 대기하세요.
추가 서비스를 스스로 시작하지 마세요.
```

### 3.2 분석 반복

**체크리스트 상태**: ⬜ 미분석(할당 가능) → 🔄 분석 중(중복 할당 금지) → ✅ 완료

**매 iteration:**
1. 체크리스트를 읽고 ⬜ 항목 확인. ✅/🔄는 건너뜀
2. 모든 항목 ✅이면 → 완료 (섹션 5)
3. ⬜ 서비스 **1건**을 선택, **즉시** ⬜→🔄 변경
   - **챕터 분산 원칙**: 팀원별로 서로 다른 챕터(### 절)의 서비스를 우선 할당한다.
     예) 팀원1 → `수불/대시보드/포장`, 팀원2 → `공정진행/통계`, 팀원3 → `추가 화면`
     같은 챕터 내 서비스는 다른 챕터에 ⬜가 없을 때만 허용
4. **할당 방법 (1건씩 할당)**:
   - **최초 할당**: Task 도구로 팀원 스폰 시 서비스 1건만 프롬프트에 포함. "완료 보고 후 대기" 명시
   - **후속 할당**: 팀원 완료 보고(SendMessage) 수신 → 🔄→✅ 갱신 → /clear 전송 → SendMessage로 다음 1건 할당
   - **절대 금지**: 스폰 시 복수 서비스를 한번에 할당 (팀리더 통제 불가)
5. 완료 시 🔄→✅, 요약 테이블 'UI - Named' +1 갱신. 실패 시 🔄→⬜ 복원
6. **🚨 [필수] 컨텍스트 초기화 — 반드시 아래 명령어를 정확히 실행할 것 🚨**
   팀리더가 팀원의 paneId로 컨텍스트 초기화 후 다음 서비스 할당.
   **아래 명령어를 한 글자도 변경하지 말고 그대로 실행한다 (Bash 도구 사용):**
   ```bash
   tmux send-keys -t {paneId} '/clear' && sleep 1 && tmux send-keys -t {paneId} Enter && sleep 15 && tmux send-keys -t {paneId} Enter
   ```
   **위반 시 팀원 컨텍스트가 초기화되지 않아 할당 실패.**
   - `/clear` 텍스트와 `Enter` 키를 **반드시 분리 전송** (한 번에 보내면 실패)
   - `sleep 1`: '/clear' 입력 후 Enter 전 대기 (tmux 전송 안정화)
   - `sleep 15`: /clear 처리 완료 대기 (컨텍스트 정리 시간)
   - 두 번째 `Enter`: /clear 완료 후 프롬프트 활성화
   - **팀리더가 원격 실행** (팀원 본인이 아님)
   - 초기화 완료 후 **SendMessage로 다음 1건 할당**
   - `{paneId}`는 팀원의 tmux pane ID (예: `%14`). 팀원 종료 알림의 `paneId` 필드에서 확인 가능
   **⚠️ SendMessage로 /clear를 보내거나, tmux send-keys에 '/clear' Enter를 한 줄로 합치는 것은 금지**
7. 다음 ⬜로 반복. 컨텍스트 한계까지 **절대 멈추지 않고** 계속 진행

**품질 요구사항**: SQL(목적·테이블관계·바인드변수·컬럼 상세, 비즈니스 의미 해석) | UI(레이아웃+이벤트핸들러+데이터흐름) | Java 없으면 '없음' 명시 | E2E 데이터흐름 다이어그램 | 특이 로직 별도 강조

## 4. 팀모드

**실행조건**: tmux 실행 시 활성화

### 4.0 팀원 생성 규칙 (필수)

**새로운 팀원 생성 금지.** 기존 팀원(team-lead, 분석팀원1~3, monitor)으로만 운영한다.

- **금지**: Phase별 분석(UI 분석 등)을 위해 `phase4-ui-analyzer` 같은 1회용 팀원 생성
- **권장**: 분석팀원 내부에서 **Task 도구(서브에이전트)**를 spawn하여 병렬 처리
  - 서브에이전트는 작업 완료 후 자동 정리되어 팀 구조가 깔끔하게 유지됨
  - API 사용량 절약 및 팀원 관리 오버헤드 감소

예시: 분석팀원1이 M173020380 분석 시, Phase 4 UI 분석이 필요하면 Task 도구로 서브에이전트를 생성하여 위임. 팀원 자체를 새로 만들지 않는다.

### 4.1 팀 구성

| 역할 | name | 필수 | 설명 |
|------|------|------|------|
| 팀리더 | team-lead | ✓ | 전체 관리, 업무 분배, 모니터링, 10분 틱으로 사용량 확인 |
| 분석팀원1~3 | 분석팀원1, 분석팀원2, 분석팀원3 | ✓ | 팀리더 지시에 따라 분석 수행 및 보고 |
| monitor | monitor | ✓ (최후 생성) | 사용량 조회용 pane. 최후 스폰하여 active pane 확보. usage-monitor.sh가 이 pane에 /usage 전송 |

### 4.2 사용량 모니터링 (팀리더 역할)

스킬: `/usage-monitor` | 스크립트: `docs/common/tools/usage-monitor.sh`

- **시작**: 팀원 전원 스폰 후 `/usage-monitor start` → 초기 사용량 확인 → action에 따라 업무 분배
- **매 틱**: `/usage-monitor check` → `NO_TICK`이면 유지, `TICK`이면 monitor pane `/usage` 전송 후 실측
- **할당 정책** (팀원 소집해제 금지 — 할당만 조절):
  - `normal` (<90%) → 최대 3명에게 할당
  - `stop` (≥90%) → 모든 팀원에게 신규 할당 중단. 팀원은 **대기 상태로 유지** (소집해제하지 않음). 리셋(5시간 주기) 후 재할당 재개
- **⚠️ 팀원 소집해제는 최종 종료 시에만**: 팀원 shutdown_request/TeamDelete는 모든 분석이 완료되어 팀을 해산할 때만 수행한다. 사용량 조절 목적으로 팀원을 해제하면 리셋 후 재생성 비용이 발생하므로 금지
- **종료**: 팀 해산 시 `/usage-monitor stop`

## 주의사항 (팀리더 행동 규칙)

팀리더는 **이벤트 기반** — SendMessage 수신으로 반응. **sleep+capture-pane 폴링 금지.**

### 초기화 → 메인 루프

```
[초기화] TeamCreate → 분석팀원1~3 스폰(업무 미할당) → monitor 최후 스폰
[사용량] /usage-monitor start → 사용량 확인
[업무 분배] normal이면 3명에게 ⬜ 1건씩 선택·🔄 마킹 + SendMessage 할당
          stop(≥90%)이면 전원 대기 → 리셋 후 재확인
[paneId 확인] tmux list-panes로 팀원별 paneId 매핑 (예: 분석팀원1 → %14)
[대기] 팀원 SendMessage 보고 수신 대기 (폴링 금지)
[수신 시] 보고서 확인 → 🔄→✅ → 요약 갱신 → 🚨컨텍스트 초기화(아래 명령어 정확히 실행) → SendMessage로 다음 ⬜ 1건 할당
         🚨초기화: tmux send-keys -t {paneId} '/clear' && sleep 1 && tmux send-keys -t {paneId} Enter && sleep 15 && tmux send-keys -t {paneId} Enter
[틱] /usage-monitor check → 조치
```

### paneId 확인 방법

Task 도구로 스폰한 팀원은 tmux pane에서 실행된다 (`backendType: "tmux"`).

**paneId 확인 시점:**
- 팀원 스폰 직후: `tmux list-panes -t 0:0 -F "#{pane_index} #{pane_id} #{pane_title}"` 으로 확인
- 팀원 종료 시: shutdown_approved 메시지의 `paneId` 필드에서 확인

**결합 패턴 (SendMessage + tmux send-keys):**
1. SendMessage로 작업 지시 → 팀원이 SendMessage로 완료 보고
2. 완료 보고 수신 후 → **🚨 아래 명령어를 Bash 도구로 정확히 실행하여 컨텍스트 초기화:**
   ```bash
   tmux send-keys -t {paneId} '/clear' && sleep 1 && tmux send-keys -t {paneId} Enter && sleep 15 && tmux send-keys -t {paneId} Enter
   ```
3. `/clear` 완료 후 → SendMessage로 다음 작업 할당

**주의:** SendMessage와 tmux send-keys는 동시에 사용 가능. 보고는 SendMessage, 컨텍스트 초기화는 tmux send-keys로 분리.

### 올바른 패턴

| 작업 | 올바른 방법 |
|------|-------------|
| 진행/완료 확인 | SendMessage 수신 대기 (capture-pane 금지) |
| 다음 할당 | /clear 전송(paneId) → SendMessage로 할당 |
| 상태 확인 | TaskList 조회 |
| 컨텍스트 초기화 | tmux send-keys -t {paneId} '/clear'... |

**capture-pane 허용**: 10분 이상 무응답(장애 의심), 프로세스 생존 확인, 디버깅 시만

### 보고 형식

```
SendMessage(recipient="team-lead", content="[완료] {ID} 분석 완료. 보고서: {경로}")
```

### 종료

모든 팀원 shutdown_request → `/usage-monitor stop` → TeamDelete(선택) → 최종 체크리스트 확인
