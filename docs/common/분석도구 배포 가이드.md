# Claude Code 설정 배포 가이드

> `deploy-claude-config.sh`를 사용하여 m30 프로젝트의 Claude Code 설정을 다른 MES 모듈 프로젝트에 배포하는 방법을 안내합니다.

## 개요

m30 프로젝트에서 구성한 Claude Code 환경(skills, agents, MCP 설정, 쿼리 캐시 등)을 c10, m20, m26, m42, m60, m77, m80, pda 등 다른 MES 모듈 프로젝트에 동일하게 배포할 수 있습니다.

### 배포 대상 파일

| 항목 | 설명 | 배포 시 처리 |
|------|------|-------------|
| `.claude/` | skills, agents, settings 등 Claude Code 설정 전체 | 그대로 복사 (`projects/`, `plans/` 제외) |
| `.mcp.json` | MCP 서버 설정 (sqlcl 등) | 그대로 복사 |
| `CLAUDE.md` | 프로젝트 지침 문서 | 모듈 ID 치환 (M17→대상, m17→대상) |
| `docs/common/` | 공통 도구, 문서, 이미지 | 그대로 복사 |
| `docs/analysis/` | 분석 결과 디렉토리 | 빈 디렉토리 구조만 생성 |
| `.gitignore` | Git 무시 규칙 | 필요 항목 추가 (`nul`, `.temp`, `.serena`) |
| `queries.db` | 쿼리 캐시 DB | 데이터 초기화 (스키마만 유지) |

## 사전 요구사항

- **bash** (Linux/macOS 기본 쉘)
- **rsync** (디렉토리 동기화에 사용)
- **sqlite3** (쿼리 캐시 DB 초기화에 사용)
- **sed** (CLAUDE.md 모듈 ID 치환에 사용)

```bash
# 도구 설치 확인
which rsync sqlite3 sed
```

## 사용법

### 기본 문법

```bash
./docs/common/tools/deploy-claude-config.sh [--dry-run] <대상-프로젝트-경로> [모듈ID]
```

| 인자 | 필수 | 설명 |
|------|------|------|
| `--dry-run` | 선택 | 실제 변경 없이 수행할 작업만 미리보기 |
| `<대상-프로젝트-경로>` | 필수 | 배포할 대상 MES 프로젝트 디렉토리 경로 |
| `[모듈ID]` | 선택 | 대문자 모듈 ID (생략 시 디렉토리명에서 자동 추출) |

### 단일 프로젝트 배포

```bash
# m30 프로젝트 루트에서 실행
cd /home/jji/project/mes-workspace/m30

# m20 프로젝트에 배포 (모듈 ID 자동 감지: M20)
./docs/common/tools/deploy-claude-config.sh ../m20

# 모듈 ID를 명시적으로 지정
./docs/common/tools/deploy-claude-config.sh ../m20 M20
```

### 일괄 배포

```bash
# 모든 MES 모듈에 한번에 배포
for mod in c10 m17 m20 m26 m42 m47 m60 m77 m80 pda; do
    ./docs/common/tools/deploy-claude-config.sh "../$mod"
done
```

### Dry-run (미리보기)

실제 파일 변경 없이 어떤 작업이 수행될지 미리 확인합니다.

```bash
# 단일 프로젝트 dry-run
./docs/common/tools/deploy-claude-config.sh --dry-run ../m42

# 일괄 dry-run
for mod in c10 m20 m26 m42 m60 m77 m80 pda; do
    ./docs/common/tools/deploy-claude-config.sh --dry-run "../$mod"
done
```

## 실행 단계별 상세 설명

스크립트는 6단계로 구성됩니다.

### [1/6] .claude/ 디렉토리 복사

```
rsync -a --exclude='__pycache__' --exclude='*.pyc' --exclude='projects/' --exclude='plans/' .claude/ → 대상/.claude/
```

- skills (`analyze-service`, `analyze-plsql`, `analyze-queries` 등)
- agents (`java-legacy-analyzer` 등)
- settings (`settings.json`)
- `projects/`와 `plans/`는 프로젝트별 고유 데이터이므로 **제외**

### [2/6] .mcp.json 복사

```
cp .mcp.json → 대상/.mcp.json
```

- sqlcl MCP 서버 설정을 그대로 복사
- 경로가 절대경로(`/home/jji/project/sqlcl/bin/sql`)이므로 동일 환경에서는 수정 불필요

### [3/6] CLAUDE.md 복사 + 모듈 ID 치환

```
sed -e 's/M17/대상모듈/g' -e 's/m17/대상모듈소문자/g' -e 's/B17R/B대상R/g' CLAUDE.md → 대상/CLAUDE.md
```

모듈별로 달라지는 ID를 자동 치환합니다:

| 원본 (m30 기준) | 대상 (예: m42) | 용도 |
|-----------------|---------------|------|
| `M17` | `M42` | 화면 ID, 테이블 접두사, 패키지 경로 |
| `m17` | `m42` | 소스 디렉토리, 소문자 참조 |
| `B17R` | `B42R` | 배치/NUI 서비스 ID 접두사 |

> **참고**: CLAUDE.md의 기본 템플릿이 M17 기준으로 작성되어 있어 M17→대상 치환이 이루어집니다. 배포 후 대상 모듈에 맞게 추가 수정이 필요할 수 있습니다 (예: 모듈별 고유 DAO, 스키마 정보 등).

### [4/6] docs/ 복사

```
rsync docs/common/ → 대상/docs/common/
mkdir -p 대상/docs/analysis/process/
```

- `docs/common/` : 공통 도구, 이미지, 가이드 문서 전체 복사
- `docs/analysis/` : 분석 결과 저장 디렉토리를 빈 구조로 생성

### [5/6] .gitignore 업데이트

대상 프로젝트의 `.gitignore`에 Claude Code 관련 항목을 추가합니다:

| 항목 | 설명 |
|------|------|
| `nul` | Windows NUL 파일 |
| `**/.temp/**` | 임시 파일 |
| `.serena` | Serena MCP 작업 디렉토리 |

기존에 이미 존재하는 항목은 건너뜁니다. 또한 `M20.iml` 같은 특정 모듈 iml 항목을 `*.iml`로 통일합니다.

### [6/6] queries.db 데이터 초기화

```sql
DELETE FROM queries;
DELETE FROM source_files;
VACUUM;
```

- 쿼리 캐시 DB의 데이터를 비우고 스키마(테이블 구조)만 유지
- `batch_state.json`을 `{}`로 리셋
- 대상 프로젝트에서 새로 쿼리 분석을 시작할 수 있도록 초기 상태로 설정

## 배포 후 확인사항

### 1. 필수 확인

```bash
# 대상 프로젝트로 이동
cd /home/jji/project/mes-workspace/m42

# 파일 존재 확인
ls -la .claude/ .mcp.json CLAUDE.md docs/

# CLAUDE.md 모듈 ID 치환 확인
grep -c "M42" CLAUDE.md   # M42로 치환되었는지 확인
grep -c "M17" CLAUDE.md   # M17이 남아있지 않은지 확인 (0이어야 함)
```

### 2. CLAUDE.md 수정

배포된 CLAUDE.md는 m30(M17) 기준 템플릿에서 모듈 ID만 치환된 상태입니다. 아래 항목을 대상 모듈에 맞게 수정해야 합니다:

- **프로젝트 개요**: 모듈별 업무 설명
- **DAO 빈 구성**: 모듈별 사용 스키마 확인
- **소스 디렉토리 경로**: 실제 패키지 구조에 맞게 조정
- **화면 ID 패턴**: 모듈별 대분류/중분류 규칙

### 3. MCP 서버 연결 확인

```bash
# sqlcl 경로가 유효한지 확인
cat .mcp.json
ls -la /home/jji/project/sqlcl/bin/sql
```

### 4. Claude Code 실행 테스트

```bash
# 대상 프로젝트에서 Claude Code 실행
cd /home/jji/project/mes-workspace/m42
claude
```

Claude Code 내에서 다음을 확인:
- `/analyze-service` 등 skill이 정상 로드되는지
- sqlcl MCP 연결이 가능한지

## 문제 해결

### rsync 명령을 찾을 수 없음

```bash
sudo apt install rsync   # Ubuntu/Debian
```

### sqlite3 명령을 찾을 수 없음

```bash
sudo apt install sqlite3  # Ubuntu/Debian
```

### 대상 경로 오류

```
오류: 대상 경로가 존재하지 않습니다: ../m99
```

→ 경로가 실제 존재하는지 확인합니다. 상대경로는 m30 프로젝트 루트 기준입니다.

### 기존 .claude/ 덮어쓰기 확인

대상에 이미 `.claude/` 디렉토리가 있으면 덮어쓸지 확인합니다. `y`를 입력하면 진행, 그 외 입력 시 취소됩니다.

### CLAUDE.md 치환 후 잔여 M17 참조

모듈 ID 이외의 맥락에서 `M17`이 사용된 경우(예: 주석, 설명문), 배포 후 수동으로 확인하여 수정합니다.
