읽기 전에: 이 문서는 무엇을 설명하나?

압연 SET을 이해하는 핵심은 ‘두께’라는 이름의 숫자 네 개를 구별하는 것입니다. 고객이 주문한 두께에서 시작해서, 압연할 두께를 정하고, SP 보정을 더하고, 마지막으로 SET에 사용할 눈금에 맞춥니다.

이 문서는 기존 PLTCM 압연 SET 결정 로직 분석서를 c10의 Java·서비스 XML·JSP·SQL과 다시 대조해 설명 순서를 바꾼 해설서입니다. 처음 읽는 분은 1~6장, 값이 달라진 이유를 찾는 분은 7~10장, 개발·검증 담당자는 부록까지 읽으면 됩니다.

분석 기준은 2026-09-07 현재 이 작업 폴더의 소스입니다. 운영에 배포된 코드나 운영 DB의 업무기준 값까지 대조한 결과는 아닙니다. 모든 계산 예제의 주문값·보정값·SP율은 설명용 가정이며, 실제 주문 실적이 아닙니다. 문서의 숫자는 별도 표시가 없으면 mm입니다. 기존 분석서와 실행 코드는 보존했습니다.

1. 먼저 ‘두께 네 개’만 구별하자

1.1 같은 주문에서도 네 값은 서로 다를 수 있다

예를 들어, 도금이 포함된 0.500mm 주문에서 최종 SET이 0.485mm가 나오는 것은 계산 흐름상 가능합니다. 주문두께에 들어 있는 도금두께를 빼고, 업무기준 보정과 SP 보정을 적용한 결과이기 때문입니다.

이름 쉽게 말하면 코드에서 찾는 이름
주문두께 고객이 주문서에 적은 두께. 무엇을 포함하는지는 BMT/TCT 구분에 달림 ORD_EXC_THK
압연목표두께 도금·도막과 보정 조건을 고려해 계산한 중간 두께 지역변수 crm_thk
PLTCM 출측두께 압연목표에 SP 보정을 적용하고 소수 3자리까지 절삭한 설계 목표 PLTCM_THK_TRV
PLTCM X-Ray SET 출측두께를 0.005mm 간격에 맞춘 최종 설정값 PLTCM_SET_THK_TRV

여기서 ‘출측두께’는 이 설계 코드가 만드는 목표값입니다. 설비에서 측정한 실적값을 뜻하지 않습니다. crm_thk도 이 클래스 안에서 계산할 때 사용하는 변수이며, 같은 이름의 DB 저장 컬럼으로 보아서는 안 됩니다.

최종 결과는 제조사양 테이블 TB_C10_QLT_DSN_MNF에 저장됩니다. 저장 단위는 주문번호 + 주문행 + 제조구분입니다. 같은 주문이라도 적정(1)과 차선(2) 행이 따로 있을 수 있습니다. [근거 S1, S3]

1.2 주문두께에 무엇이 포함되어 있나?

철판을 여러 층으로 쌓인 단면이라고 생각하면 쉽습니다. 아래 그림은 포함 관계를 설명하는 모식도이며 실제 층 두께 비율은 아닙니다.

주문두께구분 코드 이해할 기준 일반 계산에서의 출발점
BMT 1 소지 자체의 두께 주문두께
TCT 2 도금이 포함된 두께 주문두께 − 목표도금두께
칼라 TCT 3 도금·도막까지 포함된 두께 주문두께 − 전면도막 − 후면도막 − 목표도금두께

이 표는 기본 개념입니다. TCT라도 고객요청 경로를 타거나 두께관리코드 5가 적용되면 도금 차감 방식이 달라집니다. 3장의 분기표를 함께 보아야 실제 코드 결과를 알 수 있습니다.

도금·도막 두께는 입력이 µm라서 1,000으로 나누어 mm로 바꿉니다. 예를 들어 20µm = 0.020mm입니다. 코드의 GAL_THK_TRV는 이미 목표도금두께 값이므로 여기서 임의로 두 배를 하지 않습니다. 도막은 전면 값과 후면 값을 각각 더합니다. [근거 S1: 341~352행, 361~366행]

2. 모든 주문이 계산식을 처음부터 타는 것은 아니다

숫자를 대입하기 전에 먼저 어느 경로에서 만들어진 값인지 확인해야 합니다.

2.1 현재 값이 복사된 값인 경우

반복주문 복사: 저장소의 운영용 배치 설정 파일이 연결한 B10R0030_sub-service에서는 반복표시가 X이고 특기사항이 비어 있으며, 품명에 따른 참조 주문 일치 조건까지 통과한 경로에서 제조사양을 복사합니다. 이때 C102100170.MNFinsert SQL이 SET과 출측두께도 함께 가져옵니다. 참조 조건이 맞지 않으면 일반 설계 경로로 갑니다. 현재 기준으로 새로 계산한 값이라고 가정하면 안 됩니다. 별도 변형 서비스에는 다른 분기가 있으므로 배치 연결까지 확인했습니다. [근거 S5]

구매반제품 차선 복사: 일반 두께설계 안에서도 제조구분이 적정 1이 아니고, 원자재코드 첫 글자가 H나 M이 아니며, 품명이 5·7이 아니면 계산을 조기에 종료합니다. 이후 SQL이 같은 주문의 적정 행에서 두께·SET·소둔/CGL 값을 복사합니다. 여기서 ‘구매반제품 차선’은 이 코드 조건에 붙인 설명입니다. [근거 S1: 387~393행, S3]

복사할 적정 행의 설계가 실패했다면 차선에 정상 값이 생긴다고 보장할 수 없습니다. 복사 경로에서는 원본 행의 성공 여부도 함께 확인해야 합니다.

2.2 품명 5·7은 별도 처리한다

알루미늄칼라 5, 스테인레스칼라 7은 이 코드에서 일반 압연목표 계산을 건너뜁니다. SET = 주문두께이고 0.005mm 정규화도 하지 않습니다. 예를 들어 주문두께가 0.503이면 SET도 0.503입니다.

같은 코드에서 출측두께는 초기값 0을 따라 0.0이 됩니다. 따라서 이 두 품명에서 ‘출측두께 0, SET은 주문두께’가 보이면 일반 제품의 공식으로 설명하려고 하면 안 됩니다. 이것은 확인된 현행 코드 동작이며, 업무상 그 값이 적절한지는 별도 판단 대상입니다. [근거 S1: 395~655행, 738~758행]

앞의 경로를 하나의 그림으로 모으면 다음과 같습니다.

3. 일반 자동설계: 먼저 압연목표두께를 정한다

이 장은 복사 경로와 품명 5·7을 제외한 경우입니다.

3.1 보정값을 어디에서 가져오는가?

코드의 실제 질문은 ‘고객요청압연두께 숫자가 0이고, 주문두께구분이 3이 아닌가?’입니다.

고객요청 값 주문두께구분 선택되는 경로
0 1 또는 2 업무기준 C10B2060의 단위와 보정값 사용
0이 아님 1·2·3 고객사양의 단위와 요청값 사용
0 3, 칼라 TCT 고객사양 처리 쪽으로 진입. C10B2060 조회 안 함

‘요청값 0’은 이 분기에서는 미지정으로 취급됩니다. 또한 칼라 TCT는 고객요청이 없어도 업무기준 경로를 타지 않습니다. 고객요청 값 0에 고객 단위까지 공백이면 도금·도막을 뺀 값을 압연목표로 사용합니다. [근거 S1: 418행, 642~653행]

3.2 CRN·PCN·TRK는 숫자를 읽는 방법이다

‘고객요청압연두께’라는 이름만 보고 항상 확정 두께라고 읽으면 안 됩니다. 같은 컬럼의 숫자라도 함께 있는 단위에 따라 뜻이 달라집니다.

단위 쉬운 뜻 기준 두께 0.500에서의 설명용 예
CRN mm를 더한다. 음수이면 뺀다 값 +0.010 → 0.510
PCN %만큼 더한다 값 +1.0 → 0.500 + 0.005 = 0.505
TRK 그 값으로 정한다 값 0.470 → 0.470

따라서 CRN 값 0.010은 ‘두께를 0.010으로 만들어라’가 아니라 ‘0.010mm를 더해라’입니다. TRK는 TCT의 업무기준 경로에서 도금이 한 번 더 빠질 수 있으므로 다음 표까지 읽어야 합니다.

3.3 업무기준 경로의 기본 산식

아래는 관리코드 5·6 특례가 없는 정상 조합의 산식입니다. t는 주문두께, g는 목표도금두께(mm), c는 C10B2060 보정값입니다.

업무기준 단위 BMT(1)의 압연목표 TCT(2)의 압연목표
CRN t + c t − g + c
PCN t + t × c / 100 t − g + t × c / 100
TRK* c c − g

PCN의 TCT 식에서 퍼센트를 곱하는 기준은 도금을 빼기 전의 주문두께 t입니다. (t−g) × (1+c/100)과 다릅니다.

CRN + TCT는 계산 직후 소수 4자리까지 반올림하는 처리가 추가로 있습니다. 다른 분기에 일괄 적용되는 처리가 아닙니다. TRK*로 적은 마지막 행은 코드상 ‘CRN도 PCN도 아닌 나머지’ 분기입니다. 정상 코드값으로는 TRK를 뜻하지만, 잘못된 단위도 그 분기에 들어갈 수 있습니다. [근거 S1: 499~639행]

3.4 고객요청 경로의 산식

먼저 기준 두께 b를 만듭니다. 칼라 TCT(3)이면 b = t − 전면도막 − 후면도막 − g입니다. 그 외에는 b = t입니다. 그다음 고객 단위와 요청값 r을 적용합니다.

고객 단위 압연목표두께
CRN b + r
PCN b + b × r / 100
TRK r
공백 또는 그 외 b

여기서는 일반 TCT(2)의 도금두께를 자동으로 빼지 않습니다. 업무기준 TCT 공식과 같은 것으로 보면 결과가 어긋납니다. 예를 들어 TCT 0.500, 도금 0.020, CRN +0.003이라도 업무기준 경로의 압연목표는 0.483, 고객요청 경로는 0.503입니다.

칼라 TCT 식에는 라미나두께를 더하는 항도 있지만, 현재 클래스는 그 변수를 0으로 초기화하고 다른 값을 넣지 않습니다. 실제 계산에서는 0입니다. [근거 S1: 258행, 642~653행]

3.5 C10B2060은 ‘답을 찾아오는 조건표’다

코드가 보정값을 고정 숫자로 가지고 있는 것은 아닙니다. 품명, 규격기관·규격약호, 용도, 고객사, 주문두께구분, 두께관리코드, 도금량코드, 주문두께, 적용폭을 업무기준 조회에 넘깁니다. 맞는 기준이 한 건이면 그 단위와 보정값을 씁니다.

0건이면 KK82, 여러 건이면 KK83으로 해당 제조사양의 두께설계가 실패합니다. ‘없으면 보정 0으로 계산’하는 기준이 아닙니다. 어떤 경계값을 포함하는지와 어떤 행이 맞는지는 저장된 연산자·최솟값·최댓값·유효기간에 달려 있습니다. 코드만으로 실제 보정값을 확정할 수 없습니다.

슬리팅 그룹수가 0보다 크면 이 조회의 적용폭은 ORD_MIX_WTH1~10의 합계입니다. 그 외에는 주문폭입니다. 따라서 주문두께가 같아도 폭이나 고객사 조건이 달라져 다른 보정기준을 고를 수 있습니다. [근거 S1: 313~319행, 451~497행, S11]

4. 압연목표를 출측두께와 SET으로 바꾸는 두 단계

4.1 SP 보정을 하고, 소수 3자리까지 자른다

일반적인 흐름은 아래와 같습니다.

절삭 전 출측두께 = 압연목표두께 + 압연목표두께 × SP보정율 / 100
저장할 출측두께 = 위 결과의 소수 4번째 자리부터 버린 값

예를 들어 0.605 + 0.605 × 0.6 / 100 = 0.60863이면 출측두께는 0.608입니다. 0.609로 반올림하지 않습니다.

SP보정율은 C10B2070에서 품명·재질·Spangle구분·주문두께·적용폭으로 조회합니다. 여기서는 압연목표에 추가로 적용하는 두께 보정율로 이해하면 됩니다. 보정율 숫자의 물리적 산정 근거까지 이 코드에 들어 있지는 않습니다.

SP를 생략하는 경우도 있습니다. 고객 단위 THK_COR_UNT가 TRK이면 압연목표를 SP 없이 출측 계산값으로 사용한 뒤 절삭합니다. 업무기준의 TRK 처리에서는 SP율 자체를 0으로 바꿉니다. 두 단위는 서로 다른 변수이므로, ‘최종 선택 단위 하나만 보면 된다’고 단순화하면 예외를 놓칩니다. 상세 예외는 부록 A에 있습니다. [근거 S1: 397~416행, 626행, 738~750행]

SP 조회 중 MasterDataException이 나면 로그를 남기고 초기 0%로 진행합니다. 코드에 중복건수 검사가 없고 첫 결과를 읽습니다. 단, 다른 종류의 예외까지 모두 0%로 처리한다고 보장할 수는 없습니다.

4.2 출측두께를 0.005mm 간격으로 맞춘다

출측두께를 소수 3자리로 만든 다음, 소수 세 번째 숫자를 봅니다.

세 번째 숫자 최종 처리 예
0 또는 5 그대로 0.540 → 0.540 / 0.545 → 0.545
1 또는 2 세 번째 숫자를 0으로 0.542 → 0.540
3·4·6·7 세 번째 숫자를 5로 0.544 → 0.545 / 0.547 → 0.545
8 또는 9 두 번째 자리까지 남기고 0.01 더함 0.548 → 0.550 / 0.998 → 1.000

이렇게 얻는 정상 SET은 0.500, 0.505, 0.510 같은 5µm 간격입니다. 소수 3자리 출측값을 기준으로 보면 가까운 0.005mm 눈금으로 옮기는 방식입니다. 그래서 항상 올리는 것도, 항상 내리는 것도 아닙니다. DB가 0.61로 표시해도 0.610과 같은 숫자입니다. [근거 S2: 332~396행]

4.3 ‘먼저 절삭’ 순서를 바꾸면 답이 바뀐다

설명용으로 절삭 전 출측두께가 0.2029인 상황을 생각해 봅시다.

처리 방법 중간값 최종 SET
현행 순서: 소수 3자리 절삭 → SET 눈금 0.202 0.200
소수 3자리 반올림으로 바꾼 경우 0.203 0.205
절삭 없이 곧바로 가까운 0.005에 반올림 0.2029 0.205

따라서 새 프로그램에서 ‘반올림이면 되겠지’ 하고 바꾸면 이 예에서는 SET이 0.005mm 달라집니다. 정상 양수·일반 표기 범위에서 설명한 예이며, 비정상 입력과 과학적 지수 표기까지 보장하는 일반 수치 함수는 아닙니다.

5. 주문 한 건을 처음부터 끝까지 계산해 보자

5.1 도금 제품 TCT 0.500mm → SET 0.485mm

설명용 조건은 GI, TCT(2), 관리코드 5·6 미적용, 고객요청 값 0, 고객 단위 공백입니다. 업무기준이 CRN +0.003, 목표도금두께가 20µm, SP가 0.8%로 조회되었다고 가정합니다.

  1. 단위 변환: 목표도금두께 20µm ÷ 1,000 = 0.020mm.
  2. 경로 선택: 고객요청 값 0이고 TCT(2)이므로 C10B2060 업무기준 경로.
  3. 압연목표 계산: 0.500 − 0.020 + 0.003 = 0.483. CRN·TCT의 소수 4자리 반올림을 거쳐도 0.483.
  4. SP 적용: 0.483 + 0.483 × 0.8 / 100 = 0.486864(수학적 값).
  5. 출측두께 절삭: 소수 4번째 자리부터 버려 0.486.
  6. SET 눈금 적용: 세 번째 숫자가 6이므로 0.485.

이 주문의 두께 세 개를 함께 읽으면 주문 0.500 / 출측 0.486 / SET 0.485입니다. 서로 역할이 다르므로 반드시 같은 숫자여야 하는 것은 아닙니다. 다만 이 예는 계산을 설명하는 것이며, 실제 정상 저장에는 뒤이은 제조표준 조회 등의 성공도 필요합니다.

5.2 서로 다른 주문·보정 조건을 비교해 보자

다음 표의 일반 제품은 관리코드 특례가 없고, 별도 설명이 없으면 고객 단위는 공백입니다. ‘고객 CRN’ 행만 고객사양 경로입니다.

설명용 사례 압연목표 계산 출측두께 SET
CR·BMT 0.600 / 기준 CRN +0.005 / SP 0.6% 0.600 + 0.005 = 0.605 0.608 0.610
GI·TCT 0.500 / 도금 20µm / 기준 CRN +0.003 / SP 0.8% 0.500 − 0.020 + 0.003 = 0.483 0.486 0.485
CR·BMT 0.800 / 기준 PCN 1.5% / SP 0% 0.800 + 0.800 × 1.5% = 0.812 0.812 0.810
GI·TCT / 기준 TRK 0.470 / 도금 15µm 0.470 − 0.015 ≈ 0.455 0.454* 0.455
도금칼라·칼라TCT 0.500 / 앞15+뒤10µm / 도금20µm / 고객 CRN +0.010 / SP 0% 0.500 − 0.015 − 0.010 − 0.020 + 0.010 ≈ 0.465 0.464* 0.465
알루미늄칼라(5) / 주문 0.503 일반 압연목표 계산 생략 0.000 0.503

*는 현행 double 연산의 오차가 절삭에 영향을 주는 예입니다. 0.470 − 0.015가 컴퓨터 내부에서는 0.45499999999999996처럼 표현될 수 있고, 문자열을 세 자리에서 자르면 0.454가 됩니다. 위 사례는 코드 연산 순서를 JavaScript로 재현한 결과이며 운영 Java 실행 결과를 실측한 것은 아닙니다.

현재 코드와 같은 결과가 필요한 재구축에서는 이 차이까지 검증해야 합니다. 소수 연산을 정확하게 바꾸는 것과 기존 결과를 그대로 재현하는 것은 각각 확인할 목표입니다. 특히 4.3절처럼 SET 눈금 경계에 걸리면 출측 0.001 차이가 SET 0.005 차이로 이어질 수 있습니다.

5.3 같은 주문에서 고객사양 유무만 달라지면?

TCT 0.500, 도금 0.020, CRN 숫자 +0.003, SP 0%를 고정하고 보정 출처만 바꿔 봅시다.

보정 출처 압연목표 계산 출측 SET
C10B2060 업무기준 0.500 − 0.020 + 0.003 0.483 0.485
고객사양 CRN 요청값 0.500 + 0.003 0.503 0.505

차이는 ‘보정 숫자’가 아니라 선택된 경로의 도금 차감 방식에서 생깁니다. 고객사양을 변경한 뒤 SET이 달라졌다면 이 분기부터 확인하는 것이 좋습니다.

6. SET이 정해진 뒤에는 어디에 쓰이나?

SET은 최종 표시 숫자이면서, 여러 업무기준을 고를 때 사용하는 입력입니다. SET이 달라지면 다른 두께 구간의 기준이 선택될 수 있습니다. 다만 같은 기준 구간 안에서 움직이면 결과가 그대로일 수도 있습니다.

6.1 SET으로 조회하는 대표 기준

기준 무엇을 정하나? 함께 보는 대표 조건
C10B1051 제조표준: 소둔·CGL 설정값 제조표준번호, 품명, 재질, SET, 적용폭
C10B2190 PLTCM 두께 하한·상한 SET으로 공차 조회 후 각각 SET + 부호 있는 공차

예를 들어 공차가 하한 −0.010, 상한 +0.015로 조회되었다고 가정하면, SET 0.485의 두께 범위는 0.475~0.500입니다. ‘−0.010을 다시 빼서 0.495’로 계산하지 않습니다. 공차의 부호를 포함한 값을 더합니다. 이 공차 숫자도 설명용입니다.

소둔·CGL의 실제 온도나 속도, W/R 종류, Sleeve 여부는 업무기준 조회 결과입니다. 이 문서에서 임의의 운영 설정값을 제시하지 않습니다. [근거 S6, S7]

6.2 SET이 아닌 출측두께를 쓰는 곳도 있다

C10B1074, PLTCM 자체 폭수축 기준은 PLTCM_THK_TRV, 즉 출측두께로 조회합니다. SET과 혼동하기 가장 쉬운 부분입니다.

F/H 중간재의 C10B2310 경로는 기준 조회에 주문두께를 쓰고, 조회한 두께 범위를 출측두께에 더해 원자재 하한·상한을 만듭니다. 원자재 목표도 출측두께입니다. 모든 원자재 두께가 SET에서 시작하는 것은 아닙니다. [근거 S6: 1451행, S7: 675~706행]

6.3 원자재 C10B1071 경로에도 진입 조건이 있다

원자재코드가 H/M으로 시작하고 중간재 적용 경로가 아닐 때 C10B1071을 사용합니다. 주공정·대체공정1·대체공정2의 PLTCM폭 중 최대폭을 쓰며, Edge가 N/C이면 조회용 폭에 20mm를 더합니다. 이 +20은 해당 원자재두께 기준의 조회조건 보정입니다.

조회된 후보두께로 범위를 만들 때는 일반적인 ‘모든 값의 최솟값/최댓값’이 아니라, 공백·NULL과 0을 제외하는 비교 함수를 사용합니다. 구매한 냉연·도금 중간재 등은 해당 중간재 두께 경로를 따릅니다. [근거 S7, S2: 219~237행]

7. 화면에서 보이는 값은 언제 달라지나?

7.1 SET 셀을 직접 고치는 방식은 아니다

품질설계결과의 TAB05·TAB06에서 SET 셀은 읽기 전용입니다. 사용자가 출측두께를 고치면 화면 JavaScript가 0/5 규칙으로 SET을 다시 계산합니다. 저장 서비스는 화면에서 받은 SET과 출측두께를 DB에 저장합니다. 이 경로가 DbSearchThkSizeData의 전체 자동설계를 다시 실행하는 것은 아닙니다. [근거 S4]

그러므로 ‘SET 셀이 읽기 전용이니 사람이 SET을 바꿀 수 없다’는 설명은 틀립니다. 출측두께 수정을 통해 간접적으로 바뀔 수 있습니다. 공차·W/R·Sleeve·폭수축까지 자동설계 기준으로 모두 다시 조회한다고도 볼 수 없습니다.

화면 구현은 서버 구현과 완전히 같지 않습니다. 8·9 자리 올림을 JavaScript 실수 덧셈으로 처리하고 서버의 후속 절삭이 없어서, 긴 소수 꼬리가 생길 수 있습니다. 화면 범위 비교도 문자열 비교를 사용합니다. 따라서 자동설계값과 수동 수정값은 생성 경로를 함께 확인해야 합니다.

7.2 ‘압연Set지정’ 체크와 SET 숫자는 구별한다

체크박스가 저장하는 것은 공통사양의 PLTCM_SET_THK_LNK_TP라는 1/0 플래그입니다. 두께 숫자인 PLTCM_SET_THK_TRV와 별개입니다. 현재 c10 내부 자동 산식에서 이 플래그를 읽어 두께를 결정하는 분기는 확인되지 않았습니다. 외부 시스템에서 어떤 의미로 사용하는지는 확인이 필요합니다.

7.3 재설계와 반복복사의 결과가 다른 이유

재설계는 기존 제조사양을 지우고 품질설계 절차를 다시 실행하며, 압연Set지정 플래그도 초기화합니다. 현재의 주문·사양·기준에 따라 다시 만들어지므로 수동 수정값이 사라질 수 있습니다.

반면 반복복사는 참조 주문 값을 가져오는 경로입니다. 기준표를 바꿨더라도 복사 경로의 값은 새로 계산된 값과 다를 수 있습니다. [근거 S5, S10]

지금까지 설명한 네 가지 생성 경로를 저장 위치와 연결하면 다음과 같습니다.

8. 실제로 값을 추적할 때는 이 순서로 보면 된다

  1. 대상을 한 행으로 좁힌다. 주문번호, 주문행, 제조구분을 함께 확인한다. 적정과 차선을 섞어 비교하지 않는다.
  2. 생성 경로를 확인한다. 자동설계인지, 반복복사인지, 구매반제품 차선 복사인지, 화면 수정 이력이 있는지 확인한다.
  3. 입력과 단위를 모은다. 품명, 주문두께구분, 관리코드, 주문두께, 도금·도막, 고객요청 숫자와 단위를 확인한다.
  4. 선택한 기준을 확인한다. 자동계산이면 C10B2060 조회 여부, 맞은 기준 한 건, C10B2070 SP율, 적용폭을 확인한다.
  5. 중간값을 순서대로 적는다. 압연목표 → SP 적용 전후 → 소수 3자리 절삭 → SET 눈금. 계산기를 한 번만 눌러 답을 비교하지 않는다.
  6. 저장과 오류를 확인한다. SET을 계산했어도 뒤의 제조표준 조회가 실패했는지, 원본 복사 행이 정상인지, 제조사양 저장값과 화면 수정 이력이 무엇인지 확인한다.

9. 정상 공식만으로 설명하면 안 되는 현행 예외

9.1 두께관리코드 5·6은 공식 자체를 바꾼다

코드 주석의 의미는 5 = TCT 주문을 BMT로 관리, 6 = BMT 주문을 TCT로 관리입니다. 단순히 화면 표시만 바꾸는 코드가 아닙니다.

업무기준 CRN에서는 TCT+5이면 압연목표가 주문두께 그대로이고, BMT+6이면 주문두께 − 도금두께입니다. 두 경우 모두 기준의 가산 보정값을 적용하지 않습니다.

업무기준 PCN 또는 TRK 계열에서는 같은 조합의 계산문이 주석 처리되어 있습니다. 따라서 압연목표가 초기값 0으로 남고 출측·SET도 0이 될 수 있습니다. 이를 ‘0이 올바른 압연 설정값’이라는 업무 규칙으로 해석해서는 안 됩니다. 이후 제조표준 기준에 두께 0이 매칭되는지에 따라 오류 또는 0 저장으로 갈릴 수 있습니다. 전체 조합은 부록 A에 있습니다. [근거 S1: 503~626행]

9.2 SET 계산 성공과 설계 저장 성공은 다르다

SET을 구한 뒤 같은 클래스에서 C10B1051 제조표준을 조회합니다. 여기서 0건이면 KK13, 중복이면 KK14로 실패하므로 SET 숫자가 계산됐더라도 해당 행의 정상 UPDATE까지 가지 못할 수 있습니다.

반대로 오류가 있으면 주문 전체의 모든 값이 반드시 롤백되는 구조도 아닙니다. 해당 서비스의 행 단위 실패는 오류를 기록하고 루프를 계속하며, DbSetCommit의 현재 구현은 롤백 부분이 주석 처리되어 있습니다. 여기서 확인한 명시적 실패 경로에서는 이미 갱신한 다른 행의 값이 남을 수 있습니다. 모든 런타임 예외의 최종 트랜잭션 결과까지 단정하는 것은 아닙니다. [근거 S3, S12]

9.3 정합성검사는 ‘숫자가 정상’까지 보장하지 않는다

제조사양 정합성검사는 정렬된 조회 결과의 첫 행을 검사합니다. 정상 구성에서는 적정(1) 행입니다. 품명 5·7은 제조사양 검사에서 제외됩니다.

SET NULL은 CF25, 출측두께 NULL은 CF26입니다. 그러나 이 검사에서 SET 0이나 음수를 직접 걸러내는 양수 검증은 확인되지 않습니다. NULL 누락 검사를 통과했다는 사실만으로 올바른 두께라고 판단해서는 안 됩니다. [근거 S8]

10. 생산가부의 ‘압연목표두께’와 왜 다를 수 있나?

생산가부의 DbSearchPrdInqchkData도 유사한 계산을 해서 ROL_TAR_THK를 만듭니다. 하지만 품질설계의 SET과 구현이 같지 않습니다.

비교할 지점 품질설계 생산가부
관리코드 5·6 별도 산식·일부 빈 분기 존재 같은 분기 없음
업무기준 TRK와 SP SP율을 0으로 변경 해당 업무기준 경로에서 SP 적용
고객요청 값 0 일반 1·2는 업무기준 경로 고객 단위 CRN/PCN이면 고객 경로 진입 가능

또한 톤당길이 팝업 C105000010pop04의 SET 표시는 주문두께에서 도금만 빼는 별도 간이 계산입니다. 이 팝업값을 정식 품질설계 SET 계산의 검증 기준으로 사용하면 안 됩니다. [근거 S13]

A.1 C10B2060 경로 전체 조합

진입 조건은 고객요청 숫자 = 0이고 주문두께구분 ≠ 3이며, 특수품명·차선복사 경로가 아니어야 합니다. 아래는 정상 두께구분 1·2에 대한 표입니다. c는 기준값, g는 mm 환산 도금두께, t는 원래 주문두께입니다.

기준 단위 두께구분 관리코드 압연목표 / 처리
CRN TCT 2 5 t, 소수 4자리 반올림
CRN TCT 2 그 외(6 포함) t − g + c, 소수 4자리 반올림
CRN BMT 1 6 t − g
CRN BMT 1 그 외(5 포함) t + c
PCN TCT 2 6 KK94 실패
PCN TCT 2 5 계산문 없음 → 초기값 0
PCN TCT 2 5·6 외 t − g + t × c / 100
PCN BMT 1 5 KK94 실패
PCN BMT 1 6 계산문 없음 → 초기값 0
PCN BMT 1 5·6 외 t + t × c / 100
TRK 계열* TCT 2 6 KK94 실패
TRK 계열* TCT 2 5 계산문 없음 → 초기값 0, SP=0
TRK 계열* TCT 2 5·6 외 c − g, SP=0
TRK 계열* BMT 1 5 KK94 실패
TRK 계열* BMT 1 6 계산문 없음 → 초기값 0, SP=0
TRK 계열* BMT 1 5·6 외 c, SP=0

* 실제 코드는 CRN/PCN 외 else입니다. CRN에는 PCN/TRK와 같은 KK94 불일치 검사가 없습니다. 두께구분 1·2·3 이외의 비정상 값이 들어오면 일부 분기가 BMT 쪽으로 흐를 수 있으며, 이 표가 그 입력의 업무 유효성을 승인하는 것은 아닙니다.

A.2 SP 적용의 정확한 판정

코드에서는 고객 단위 thk_cor_unt와 기준 조회 결과의 단위를 별도로 읽습니다. 업무기준 단위를 고객 변수에 복사하지 않습니다.

  1. 업무기준 TRK 계열 분기를 지나면 sp_thk = 0이 됩니다.
  2. 이후 고객 단위가 TRK이면 출측 계산값 = crm_thk입니다.
  3. 그 외에는 crm_thk + crm_thk × sp_thk / 100입니다.
  4. 어떤 경우든 이후 thk_dot을 적용합니다.

따라서 고객요청 숫자가 0이어서 업무기준 CRN/PCN 경로에 들어갔더라도, 고객 단위에 TRK가 남아 있으면 SP가 생략됩니다. 또한 칼라 TCT는 요청값 0이어도 고객 경로에 들어가므로, 이때 고객 단위가 TRK면 압연목표 자체가 0입니다. [근거 S1: 329~330행, 503~626행, 651~652행, 738~750행]

A.3 제품두께·공차는 SET과 어떻게 구별하나?

COR_THK_TRV는 품명별 제품목표두께입니다. 일반적으로 냉연은 압연목표, CR칼라는 압연목표+도막, 도금제품은 압연목표+도금, 도금칼라는 압연목표+도막+도금을 사용합니다. 이 제품목표가 출측이나 SET을 대신하지 않습니다.

PRD_THK_RNG_*와 PRD_THK_SPC_RNG_*는 제품 보증·규격 범위입니다. 인수도공차와 제품두께계산적용코드 T/C 등이 이 범위 계산에 관여합니다. 이 코드들은 최종 SET의 0/5 규칙을 바꾸는 스위치가 아닙니다.

칼라 TCT는 앞 단계에서 지역변수 ord_exc_thk를 도금·도막 차감값으로 바꾼 뒤 제품범위 계산에서도 재사용합니다. 원래 주문두께로 다시 바꿔 대입하면 현행 결과와 달라질 수 있습니다. 품명 H/S/U/X 등은 이 클래스의 제품범위 산식 그룹에 들어 있지 않아 일부 제품두께 결과가 초기값 0으로 남을 수 있습니다. [근거 S1: 642~735행]
