## 2. 시스템 목적

품질설계 수정이력현황 화면은 코일(주문) 단위의 품질설계 제조 조건 변경 이력을 조회하는 시스템이다. 품질 담당자가 특정 주문에 대해 설계 제조 조건이 언제, 어떻게 변경되었는지를 추적할 수 있도록 변경 전후의 값을 함께 제공한다.

주요 조회 대상은 도금(CGL/EGL), 냉연(TM), 소둔(일반소둔/상자소둔) 등 각 제조 공정별 목표 품질 조건으로, 두께·폭·온도·속도 등의 설계 파라미터에 대해 변경 전 값과 변경 후 값을 나란히 비교하여 확인할 수 있다.

이 화면은 품질 이력 추적 및 변경 사유 감사(Audit) 목적으로 사용되며, 별도의 데이터 입력이나 저장 기능 없이 순수 조회만을 제공한다. 조회 기간(품질설계수정일자)과 주문번호·행번 조건으로 필터링하여 해당 범위의 변경 이력 목록을 확인할 수 있다.

## 7. 주요 유즈케이스

<details>
<summary>UC-01: 기간 조건으로 품질설계 수정이력 조회</summary>

- **Actor**: 품질 담당자
- **목적**: 품질설계수정일자 범위를 기준으로 변경된 제조 조건 이력을 조회하여 변경 전후 값을 비교 확인한다.
- **주요 흐름**:
  1. 화면 진입 시 시스템이 종료일을 오늘, 시작일을 1개월 전으로 자동 설정하고 초기 조회를 실행한다.
  2. 담당자가 조회 기간(시작일~종료일)을 변경하거나 주문번호·행번 조건을 입력하여 조회를 요청한다.
  3. 시스템이 날짜 유효성(필수 입력, 시작일 ≤ 종료일)을 검증하고 조건에 맞는 이력 목록을 반환한다.
  4. 담당자가 이력 목록에서 변경 전후 파라미터 값을 확인한다.
- **예외**: 날짜 미입력 또는 시작일 > 종료일인 경우 오류 메시지를 표시하고 조회를 중단한다.

</details>

<details>
<summary>UC-02: 주문번호 기준으로 특정 코일의 품질설계 수정이력 조회</summary>

- **Actor**: 품질 담당자, 생산 관리자
- **목적**: 특정 주문(코일)에 대해 어떤 품질설계 제조 조건이 몇 번에 걸쳐 변경되었는지 이력 순서(MDF_SEQ)별로 확인한다.
- **주요 흐름**:
  1. 주문번호(ORD_NO)와 필요 시 행번(ORD_LN)을 입력하고 조회 기간을 설정한다.
  2. 시스템이 해당 주문의 수정 이력을 수정일시(MDF_DH) 오름차순으로 정렬하여 반환한다.
  3. 담당자가 변경 순서별로 변경된 제조구분, 두께, 폭, CGL/TM/소둔 조건 등의 변경 전후 값을 비교한다.
- **예외**: 주문번호 조건 입력 시 날짜 조건이 없으면 전체 기간으로 자동 적용된다.

</details>

<details>
<summary>UC-03: 조회 결과 엑셀 다운로드</summary>

- **Actor**: 품질 담당자
- **목적**: 조회된 품질설계 수정이력 데이터를 엑셀 파일로 내보내어 별도 분석이나 보고 자료로 활용한다.
- **주요 흐름**:
  1. 담당자가 원하는 조건으로 이력 목록을 조회한다.
  2. 컨텍스트 메뉴에서 엑셀 다운로드를 선택한다.
  3. 시스템이 현재 그리드의 전체 데이터를 엑셀 파일로 내보낸다.
- **예외**: 해당 없음.

</details>

## 9. 관련 엔티티

### 엔티티 목록

| 엔티티(테이블) | 설명 | 사용 유형 |
|----------------|------|----------|
| C10APUSER.TB_C10_QLT_DSN_MNF_MDF_LOG | 품질설계 제조 조건 변경 이력 로그. 주문(ORD_NO, ORD_LN)별로 변경 순서(MDF_SEQ)마다 변경 전후의 전체 제조 파라미터를 기록한다. | 조회 |

### 엔티티 간 관계

- TB_C10_QLT_DSN_MNF_MDF_LOG는 주문(ORD_NO + ORD_LN)과 변경 순서(MDF_SEQ)를 복합 기본키로 하며, 하나의 주문에 대해 여러 건의 수정 이력이 존재할 수 있다.
- 그리드 XML 헤더 정의에는 TB_C10_QLT_DSN_ERR가 참조 테이블로 명시되어 있으나, 실제 조회 쿼리는 C10APUSER.TB_C10_QLT_DSN_MNF_MDF_LOG 단일 테이블에서만 데이터를 읽는다.

## 11. 특이사항 및 주의사항

### 1. C10APUSER 스키마 참조

조회 대상 테이블(TB_C10_QLT_DSN_MNF_MDF_LOG)이 일반적인 MESAPUSER 스키마가 아닌 C10APUSER 스키마에 위치한다. 이는 모듈 간 공유 스키마로, 다른 모듈에서도 동일 테이블에 접근할 수 있음을 의미한다.

### 2. 날짜 조건과 주문번호 조건의 상호작용

조회 쿼리의 날짜 필터는 주문번호·행번 조건 입력 여부에 따라 동작이 달라진다. 주문번호나 행번이 입력된 경우 날짜 조건이 없으면 '1900-01-01 ~ 3000-12-31'(전체 기간)으로 자동 적용되어, 해당 주문의 전체 변경 이력을 조회할 수 있다. 반면, 주문번호·행번 모두 미입력 시에는 날짜 조건이 필수로 적용된다. 단, 화면 클라이언트 측에서는 날짜 필수 입력을 항상 강제하므로, 이 쿼리 수준의 조건 분기는 직접 쿼리 호출 시에만 실질적 의미를 갖는다.

### 3. 변경 전후 값 비교 컬럼 구조

이력 테이블(TB_C10_QLT_DSN_MNF_MDF_LOG)은 변경 후 값 컬럼과 변경 전 값 컬럼(접미사 `_BF`)을 쌍으로 저장하는 구조를 취한다. 조회 쿼리가 약 140개의 컬럼을 반환하며, 그리드에는 주요 비교 항목만 표시된다. 행 더블클릭 이벤트가 구현되어 있으나 현재 비활성화(주석 처리) 상태이다.
