## 2. 시스템 목적

CCL(Color Coated Line) 공정에서 사용되는 각종 코드(칼라코드, CCL BOM, 수지타입, Print Roll, Ink코드, 보호필름코드, 접착제코드, 생산UGS필름코드)의 사용 현황을 조회하는 화면이다. 9가지 검색유형에 따라 코드 마스터 정보(Grid_1)와 해당 코드가 실제 사용된 주문/생산 이력(Grid_2)을 연동하여 조회한다.

이 서비스는 CCL 공정 품질설계 담당자가 특정 코드의 사용 이력을 추적하거나, 코드 변경 시 영향도를 분석할 때 활용된다. 예를 들어 특정 칼라코드가 어떤 주문에 사용되었는지, 특정 CCL BOM이 어떤 고객/용도에 적용되었는지를 파악할 수 있다.

CCL_BOM_NO 또는 ROLL_CD 파라미터를 외부에서 수신하면 자동으로 해당 검색유형을 선택하고 조회를 실행하며, Grid_2에서 주문상세(C104000020), 생산이력(M472020090), 칼라물성(M472020030tab04) 화면으로 이동하는 외부 연동 링크를 제공한다.

## 7. 주요 유즈케이스

<details>
<summary>UC-01: 칼라코드 기반 사용 현황 조회</summary>

- **Actor**: CCL 품질설계 담당자
- **목적**: 특정 칼라코드(도료코드)가 어떤 CCL BOM에 매핑되어 있고, 어떤 주문/생산에 사용되었는지 추적
- **주요 흐름**:
  1. 검색유형에서 "칼라코드" 선택
  2. 코드 입력 후 조회
  3. 코드 목록(Grid_1)에서 대상 칼라코드 선택
  4. 해당 칼라코드가 사용된 CCL BOM 및 색상 매핑 정보 확인 (Grid_2)
  5. 필요 시 주문번호 링크로 주문상세 화면(C104000020) 이동
- **예외**: 검색 결과 없음 시 빈 Grid 표시

</details>

<details>
<summary>UC-02: CCL BOM 기반 사용 이력 조회</summary>

- **Actor**: CCL 품질설계 담당자
- **목적**: 특정 CCL BOM이 어떤 주문에 적용되었는지 확인하고, 기간별 사용 이력 분석
- **주요 흐름**:
  1. 검색유형 "CCLBOM코드" 선택 (기본 선택)
  2. 기간 선택 (1년/3년/전체, 기본 1년)
  3. CCL BOM 번호 입력 후 조회
  4. BOM 목록(Grid_1)에서 대상 BOM 선택
  5. 해당 BOM이 적용된 주문정보, 설계확정자, 생산완료일 등 확인 (Grid_2)
  6. 생산이력(PRD_WHS_OX) 또는 칼라물성(MPR_OX) 링크로 외부 화면 이동
- **예외**: 외부에서 CCL_BOM_NO 파라미터 수신 시 자동 조회 실행

</details>

<details>
<summary>UC-03: Print Roll 사용 현황 조회</summary>

- **Actor**: CCL 품질설계 담당자
- **목적**: 특정 Print Roll이 어떤 CCL BOM에 사용되고 있는지 파악하여 Roll 교체 시 영향도 분석
- **주요 흐름**:
  1. 검색유형 "Print Roll" 또는 "동일Print Roll" 선택
  2. Roll 번호 입력 후 조회
  3. Roll 목록(Grid_1)에서 대상 Roll 선택
  4. 해당 Roll이 사용된 CCL BOM 목록 확인 (Grid_2, 전면/후면 1~4도 컬럼)
- **예외**: 외부에서 ROLL_CD 파라미터 수신 시 자동 조회 실행

</details>

<details>
<summary>UC-04: 부자재(Ink/보호필름/접착제/UGS필름) 코드 사용 조회</summary>

- **Actor**: CCL 품질설계 담당자
- **목적**: 부자재 코드별 사용 현황을 조회하여 코드 변경 영향 범위 파악
- **주요 흐름**:
  1. 검색유형에서 해당 부자재 선택 (Ink코드/보호필름/접착제/UGS필름)
  2. 코드 입력 후 조회
  3. 부자재 코드 목록(Grid_1)에서 대상 코드 선택
  4. 해당 부자재가 사용된 CCL BOM 또는 주문 정보 확인 (Grid_2)
- **예외**: Ink코드 조회 시 전면/후면 1~4도 총 8개 필드 OR 조건으로 검색

</details>

### 엔티티 간 관계

- TB_C10_CCL_BOM은 중심 허브 테이블로, 색상코드(TB_C10_CLR_CD_MNG), 색상매핑(TB_C10_CLR_MPR), 품질설계(TB_C10_QLT_DSN_CMN)를 연결한다.
- TB_C10_CLR_MPR은 TB_C10_CCL_BOM과 CCL_BOM_NO로 1:N 관계 (하나의 BOM에 여러 고객/용도 매핑)이다.
- TB_C10_QLT_DSN_CMN은 TB_C10_CCL_BOM과 연결되며, TB_M47_PRD_ACT_CMN, TB_M60_WHS_RET와 주문번호(ORD_NO, ORD_LN)로 연결된다.
- VI_M00_CODE_ACCESS 뷰는 스칼라 서브쿼리 형태로 각 쿼리에서 코드값을 의미명으로 변환하는 데 사용된다.
- TB_M90_EMP_INF는 수정자 ID를 직원명으로 변환할 때 스칼라 서브쿼리로 참조된다.

## 11. 특이사항 및 주의사항

### 1. 9가지 검색유형별 동적 분기 처리

서비스는 사용자가 선택한 검색유형(SEARCH_CD_SEL, 값 1~9)에 따라 PosDefaultRouter와 PosValueRouter 두 단계 분기를 통해 서로 다른 SQL 쿼리 쌍(Grid_1용, Grid_2용 각각 9종)을 실행한다. 하나의 서비스 엔드포인트에서 Grid_1 조회(find 액션)와 Grid_2 연동 조회(useFind* 액션)를 모두 처리하며, 화면에서 검색유형이 바뀔 때마다 Grid 컬럼 구성도 동적으로 전환된다.

### 2. CCL BOM 사용 이력 기간 필터링

CCLBOM코드 검색유형(SEARCH_CD_SEL=2)에서만 기간 콤보(1년/3년/전체)가 활성화되며, 생산완료일(WK_END_DH) 기준으로 최근 12개월(기본), 36개월, 또는 제한 없음으로 필터링된다. 다른 검색유형에서는 기간 필터를 사용하지 않는다.

### 3. 외부 파라미터 수신 시 자동 조회

외부 화면에서 CCL_BOM_NO 또는 ROLL_CD 파라미터를 전달하면, 화면 로드 시 해당 검색유형(CCLBOM코드 또는 Print Roll)을 자동으로 설정하고 조회를 실행한다. 이를 통해 다른 화면(예: CCL BOM 설계 화면)에서 코드사용조회 화면으로 컨텍스트를 유지한 채 연결된다.

### 4. Grid_2 코드 하이라이트

Grid_2 데이터 로드 완료 후, 선택된 코드값과 일치하는 셀을 파란색 배경으로 하이라이트하여 사용자가 조회 기준 코드를 쉽게 식별할 수 있도록 한다. 검색유형에 따라 하이라이트 대상 컬럼이 달라진다.

### 5. 스칼라 서브쿼리 기반 코드값 변환 및 FUNC_DECODE01 함수 활용

조회 결과에서 코드값을 의미명으로 변환하기 위해 VI_M00_CODE_ACCESS 뷰를 스칼라 서브쿼리로 다수 조인하며, 칼라코드 사용 조회(Grid_2_CLRCD)에서는 C10APUSER.FUNC_DECODE01 Oracle 함수를 호출하여 코드를 디코딩한다. Oracle 구버전(11.2.0.3.0) 환경에서의 함수 존재 여부에 주의가 필요하다.
