## 2. 시스템 목적

업무기준조회(판단) 화면은 C10 모듈(설계/스케줄)이 주문 및 제품 정보를 기반으로 수행한 업무기준 판단 결과를 조회하는 읽기 전용 화면이다. 제품 설계 시 적용되는 각종 업무기준(설계KEY, 규격 성분/재질 사양, 인수도, 원자재 두께/발주기준, 공정별 폭마진/감소량, 압연 두께 보정, 통과공정 삭제, 제조표준, 포장재 중량 등)의 판단 결과를 20개 탭으로 분류하여 표시한다.

각 탭은 업무기준 규칙 엔진 테이블(TB_M00_RULES010, TB_M00_RULES040)을 조회하여, 특정 주문/제품에 대해 해당 업무기준 규칙(C10B10xx/C10B20xx)에 정의된 조건(CON/MIN/MAX 쌍)과 판단 결과(RST)를 표시한다. 이를 통해 설계 담당자와 품질/공정 담당자는 자동 설계 시스템이 어떤 업무기준 규칙을 적용했는지 검증하고 추적할 수 있다.

이 화면은 순수 조회 목적으로 운영되며, 데이터 수정 및 저장 기능은 없다. 메인 서비스(C107000030-service)는 탭바 컨테이너 역할만 담당하며, 실제 데이터 조회는 각 탭의 개별 서비스(C107000030tab01-service ~ C107000030tab20-service)에서 수행된다.

### 엔티티 간 관계

- TB_M00_RULES010은 업무기준 규칙 ID(MD_RULE_ID)를 정의하며, TB_M00_RULES040과 MD_RULE_ID 기준으로 1:N 관계
- TB_M00_RULES040은 TB_M00_RULES010에서 C10B10xx/C10B20xx 규칙 코드로 필터링 후, 각 탭별 업무기준에 해당하는 조건과 판단 결과를 제공

## 11. 특이사항 및 주의사항

### 1. 규칙 엔진 기반 단일 테이블 구조
모든 20개 탭이 동일한 두 테이블(TB_M00_RULES010, TB_M00_RULES040)을 조회하며, 탭별로 다른 규칙 코드(C10B10xx/C10B20xx)로 필터링한다. 업무기준 판단 데이터는 C10 모듈 내부 테이블이 아닌 M00(마스터) 스키마의 공용 규칙 엔진 테이블에 저장된다.

### 2. 탭별 결과 컬럼 수 편차
탭에 따라 결과 컬럼(RST) 수가 크게 다름: 설계KEY(RST 13개), 규격성분사양/사내성분사양(RST 40개), 원자재발주기준(RST 50개), 제조표준기준(RST 30개), 통과공정삭제(21개 조건). 가장 복잡한 탭은 원자재발주기준(tab20)으로 조건 3개, 결과 50개(화학성분+기계적 성질+도금량코드)이며, 통과공정삭제(tab17)는 조건이 21개로 가장 많다.

### 3. 메인 Form 파라미터 공유 방식
메인 화면(C107000030.jsp)의 Form(C107000030_Form_1)에서 입력된 조회 파라미터가 `uiCommon.parameters4` 메커니즘을 통해 각 탭 Grid로 전달된다. 탭 간 파라미터 공유는 상위 iframe의 Form을 직접 참조하는 방식으로 동작하므로, 메인 Form의 파라미터 변경 시 현재 활성 탭만 재조회된다.

### 4. 순수 조회 전용 화면
20개 탭 모두 Grid가 읽기 전용(ro/ron)으로 구성되며 저장(INSERT/UPDATE/DELETE) 동작이 없다. 다만, 컨텍스트 메뉴에 "편집가능" 모드 토글이 있어 사용자가 Grid를 편집 모드로 전환할 수 있으나, 실제 저장 기능은 제공되지 않는다.

### 5. 탭 자동 조회 (XLE 이벤트)
각 탭 JSP가 iframe에 로드 완료되면 XLE(onXLEEvent: onLoadGrid) 이벤트가 발생하여 자동으로 메인 Form 파라미터를 기반으로 조회를 실행한다. 탭 전환 시마다 해당 탭의 업무기준 데이터가 자동 조회되며, 별도의 조회 버튼 클릭이 필요 없다.
