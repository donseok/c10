## 2. 시스템 목적

본 시스템은 제품개발 건별 상세 현황을 통합 조회하기 위한 화면이다. 개발번호를 기준으로 개발 요청의 공통 정보, 개발요청 Spec 목록, 개발의뢰 BOM 목록, 개발완료 BOM 목록을 한 화면에서 계층적으로 확인할 수 있다.

품질설계 담당자 및 영업 담당자가 주 사용자이며, 특정 제품개발 건의 요청 이력부터 개발 완료 BOM까지의 전체 흐름을 한눈에 파악하는 데 활용된다. 개발번호 입력 후 조회하면 색상개발, 라미나개발, 잉크젯개발, 시험/분석 등 연관 개발 요소의 등록 건수도 함께 표시된다.

또한 개발요청 Spec, 개발의뢰 BOM, 개발완료 BOM 각 항목에서 해당 상세 화면(C108000070, C108000090, C108000110)으로 직접 연결되는 링크를 제공하여, 연관 업무 화면으로의 신속한 이동을 지원한다.

<details>
<summary>UC-01: 제품개발 공통 정보 조회</summary>

- **Actor**: 품질설계 담당자 / 영업 담당자
- **목적**: 특정 개발번호에 대한 개발 요청 공통 정보(요청일시, 요청자, 고객사, 용도, 사용지역, 시편 수신 정보, 개발 접수 정보 등)를 조회
- **주요 흐름**:
  1. 개발번호를 입력하고 조회를 실행
  2. 시스템이 개발 요청 공통 정보를 조회하여 화면에 표시
  3. 담당자가 개발요청 비고, 개발접수 비고, Sample MO 등 세부 정보 확인
- **예외**: 개발번호 미입력 시 조회 불가

</details>

<details>
<summary>UC-02: 개발요청 Spec 및 의뢰 BOM 계층 조회</summary>

- **Actor**: 품질설계 담당자
- **목적**: 개발번호에 연결된 개발요청 Spec 목록을 조회하고, Spec 선택 시 해당 개발의뢰 BOM 목록을 연속 조회하여 코팅방식, 색상 구성, 인쇄 구성 등 세부 BOM 내용을 확인
- **주요 흐름**:
  1. 개발번호 조회 후 개발요청 Spec 목록 표시
  2. Spec 행 선택 시 해당 개발의뢰 BOM 목록 자동 조회
  3. 개발의뢰 BOM 행 선택 시 해당 개발완료 BOM 목록 자동 조회
  4. 개발요청 Spec 링크를 통해 C108000070(Spec 상세) 화면으로 이동 가능
  5. 개발의뢰 BOM 링크를 통해 C108000090(의뢰 BOM 상세) 화면으로 이동 가능
  6. 개발완료 BOM 링크를 통해 C108000110(완료 BOM 상세) 화면으로 이동 가능
- **예외**: Spec 미선택 시 의뢰 BOM 조회 불가, 의뢰 BOM 미선택 시 완료 BOM 조회 불가

</details>

<details>
<summary>UC-03: 개발 요소 현황 확인 및 연관 화면 이동</summary>

- **Actor**: 품질설계 담당자
- **목적**: 색상개발, 특수제품후처리, BabyRoll제작, 잉크젯개발, 라미나개발, 시험/분석 각 분야별 등록 건수를 확인하고 해당 상세 화면으로 이동
- **주요 흐름**:
  1. 개발번호 조회 시 각 개발 요소별 등록 건수(색상개발, 라미나개발, 시험/분석 합산)가 자동 표시
  2. 색상개발 링크 → C108000130, 특수제품후처리 → C108000190, BabyRoll제작 → C108000150, 잉크젯개발 → C108000210, 라미나개발 → C108000170, 시험/분석 → C108000230으로 이동 가능
- **예외**: 조회된 개발번호가 없을 경우 건수는 0으로 표시

</details>

### 엔티티 간 관계

- `TB_C10_PRD_DEV_CMN`은 제품개발 건의 최상위 공통 정보이며, 개발번호(PRD_DEV_NO)를 기준으로 모든 하위 엔티티와 연결됨

- `TB_C10_PRD_DEV_REQ_BOM`은 개발번호 + 개발요청SPEC번호를 기준으로 복수의 의뢰 BOM이 존재함

- `TB_C10_PRD_CLR_DEV`, `TB_C10_PRD_LMN_DEV`, `TB_C10_PRD_TST_ANLY`는 개발번호 단위로 집계되어 개발 요소 건수로 표시됨

## 11. 특이사항 및 주의사항

### 1. 3단계 계층 연동 조회 구조
화면은 개발요청 Spec → 개발의뢰 BOM → 개발완료 BOM의 3단계 계층으로 구성되며, 상위 그리드 행 선택 시 하위 그리드가 자동 연동 조회된다. Grid_1 행 선택 시 Grid_2가, Grid_2 행 선택 시 Grid_3가 즉시 갱신된다.

### 2. 다수의 연관 화면 링크 허브 역할
본 화면은 조회 전용이지만 개발요청 Spec(C108000070), 개발의뢰 BOM(C108000090), 개발완료 BOM(C108000110), 색상개발(C108000130), 특수제품후처리(C108000190), BabyRoll제작(C108000150), 잉크젯개발(C108000210), 라미나개발(C108000170), 시험/분석(C108000230) 등 총 9개 연관 화면으로 이동하는 링크 허브 역할을 한다. 각 링크는 현재 조회 중인 개발번호를 파라미터로 전달한다.

### 3. 개발 요소 건수 집계 방식
Form_5의 개발 요소 건수는 색상개발(`TB_C10_PRD_CLR_DEV`), 라미나개발(`TB_C10_PRD_LMN_DEV`), 시험/분석(`TB_C10_PRD_TST_ANLY`) 세 테이블을 UNION으로 합산하여 조회한다. 특수제품후처리(SPC_PRD_AF_NO), BabyRoll제작(PRT_BY_ROLL_NO), 잉크젯개발(INK_DEV_NO) 건수는 이 집계 쿼리에 포함되어 있지 않으며, 표시되는 값은 Form_5 필드 초기값(0)으로 표시된다.

### 4. URL 파라미터를 통한 초기 조회 지원
외부에서 `PRD_DEV_NO` 파라미터를 URL로 전달하면, 화면 로드 시 자동으로 해당 개발번호로 조회가 실행된다. 이를 통해 다른 화면에서 특정 개발 건의 상세 현황으로 직접 진입하는 Deep-link가 가능하다.

### 5. 다중 스키마 참조
본 서비스는 C10APUSER(주 데이터), M90APUSER(사원 정보), M00APUSER(공통 코드) 세 스키마를 동시에 참조한다. 쿼리 내 서브쿼리 방식으로 코드 명칭을 변환하며, 각 스키마 권한이 모두 부여되어 있어야 정상 조회된다.
